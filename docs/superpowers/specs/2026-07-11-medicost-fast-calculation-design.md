# MEDICost 빠른 계산 사용성 개선 설계

## 상태

- 작업명: MEDICost 빠른 계산 1차 개선
- 제품 표기: 현재 `MEDICost v3.0` 유지
- 대상: 메인 페이지의 단계형 계산기
- 승인 방향: 필수 조건만으로 가장 빠르게 결과를 확인하는 흐름

## 목표

처음 방문한 사용자가 의료 용어를 몰라도 병원 등급, 진료 형태, 비급여 기준 지역만 선택해 결과를 확인할 수 있게 한다. 상병코드와 검사·시술·수술 검색은 필요할 때만 사용한다.

계산 공식, 의료 데이터, 외부 API, D1 schema, 기존 계산 결과 구조는 변경하지 않는다.

## 확인된 문제

1. 1단계 다음 이동이 항상 과밀한 선택 조건 화면으로 이어진다.
2. 선택 조건 화면에 통합검색, 분류 탭, 단계형 선택, 상병코드, 기타 처치가 동시에 노출된다.
3. 제거된 `결과보기` 버튼을 안내 문구와 빈 결과 문구가 계속 언급한다.
4. 현재 선택한 필수 조건과 추가 항목 수를 한곳에서 확인하기 어렵다.
5. 계산기를 처음 상태로 되돌리는 명확한 동작이 없다.

## 검토한 접근

### A. 빠른 결과 우선 — 채택

필수 조건 완료 후 `바로 결과 보기`와 `항목 추가하기`를 나눈다. 기본 경로는 바로 결과이며, 고급 기능은 선택적으로 접근한다.

- 장점: 가장 짧은 경로, 초행 사용자에게 유리
- 단점: 정밀 항목 기능을 발견하기 어려울 수 있어 보조 CTA와 요약이 필요

### B. 기존 3단계 유지

구조는 유지하고 문구와 간격만 정리한다.

- 장점: 변경 위험이 작음
- 단점: 선택 단계의 인지 부담이 그대로 남음

### C. 단일 페이지 실시간 계산

단계를 없애고 모든 입력과 결과를 한 화면에 둔다.

- 장점: 숙련 사용자에게 빠름
- 단점: 모바일 과밀, 기존 단계 계약과 접근성 흐름의 변경 범위가 큼

## 화면과 상호작용

### 1단계: 필수 조건

- 병원 등급, 진료 형태, 비급여 기준 지역을 유지한다.
- 하단에 두 동작을 제공한다.
  - 기본 CTA `바로 결과 보기`: 필수 조건을 검증하고 결과를 계산한 뒤 결과 영역으로 이동한다.
  - 보조 CTA `검사·치료 항목 추가`: 기존 2단계로 이동한다.
- 누락 시 기존 인라인 오류와 첫 누락 필드 focus를 사용한다.

### 2단계: 선택 조건

- 통합검색을 첫 화면의 주 기능으로 유지한다.
- 상병코드, 분류별 직접 선택, 기타 처치는 `고급 항목 열기` 아래에서 점진적으로 공개한다.
- 추가된 항목 목록은 항상 통합검색 아래에서 확인한다.
- 하단 CTA `선택 완료·결과 보기`는 즉시 계산하고 결과로 이동한다.
- 기존 DOM ID와 검색 함수 계약을 유지한다.

### 3단계와 결과

- 3단계는 실손보험 설정과 선택 요약만 보여준다.
- 결과는 1단계 또는 2단계 CTA가 계산한 값을 즉시 표시한다.
- `결과보기`를 다시 누르라는 모든 문구를 제거한다.
- 보험 설정을 변경하면 현재 결과를 즉시 다시 계산한다.
- 빠른 결과에서는 `실손보험 미적용` 상태와 `보험 설정` 바로가기를 함께 보여준다.
- 결과 상단에 `보험 설정`, `조건 수정`, `처음부터`를 제공한다.

### 선택 요약

다음 정보를 짧은 텍스트와 상태 칩으로 표시한다.

- 병원 등급
- 진료 형태
- 비급여 기준 지역
- 산정특례 적용 여부
- 상병코드 적용 여부
- 추가한 의료 항목 수

요약은 입력값을 복제 저장하지 않고 현재 DOM과 기존 추가 항목 배열에서 읽는다.

### 초기화

- `처음부터`는 폼 입력, 추가 의료 항목, 결과, 단계 상태를 초기화한다.
- 동의 설정과 저장된 비급여 기본 지역은 유지한다.
- 초기화 완료 상태를 `aria-live`로 알리고 첫 병원 등급에 focus한다.

## 코드 경계

- `frontend/index.html`: CTA, 선택 요약, 고급 항목 disclosure, 초기화 버튼의 마크업
- `frontend/assets/js/app-shell.js`: 단계 이동, 빠른 결과 경로, 요약 갱신, 초기화 진입점
- `frontend/assets/js/script.js`: 기존 계산 상태를 읽는 최소 공개 함수와 의료 항목 초기화 동작
- `frontend/assets/css/style-v3.css`: 기존 토큰만 사용한 CTA 계층, 요약, disclosure 반응형 스타일
- 계산 공식과 검색 매칭 구현은 수정하지 않는다.

## 상태와 오류 처리

- 계산 데이터 로딩 중에는 CTA를 사용할 수 없도록 현재 `inert` 계약을 유지한다.
- 필수 입력 누락은 1단계 인라인 오류로만 처리한다.
- 검색 무결과와 데이터 로드 실패의 기존 상태를 유지한다.
- 계산 데이터 로드 실패 시에는 결과 영역으로 이동하지 않고 기존 로드 오류와 재시도 상태를 유지한다.

## 접근성

- 모든 신규 버튼은 최소 44px 터치 영역을 갖는다.
- 고급 항목 버튼은 `aria-expanded`와 `aria-controls`를 사용한다.
- 선택 요약은 제목이 있는 `aside`로 제공한다.
- 단계 이동과 초기화 완료는 live region으로 알린다.
- 375px, 768px, 1280px 및 200% 확대에서 가로 넘침이 없어야 한다.
- reduced-motion에서는 결과 이동을 즉시 수행한다.

## 테스트

### 자동 검증

- 필수 조건 누락 시 빠른 결과가 실행되지 않고 첫 필드가 focus되는지 확인
- `바로 결과 보기`가 2단계를 건너뛰고 결과를 계산하는지 확인
- `항목 추가하기`가 기존 2단계 값과 검색 기능을 보존하는지 확인
- 고급 항목 disclosure 상태와 키보드 조작 확인
- 선택 요약이 입력 변경과 항목 추가·삭제를 반영하는지 확인
- 초기화가 계산 상태만 지우고 동의 설정은 유지하는지 확인
- 기존 계산·검색 회귀 테스트 유지

### 실제 Chrome 검증

- 일반 외래 빠른 결과
- 응급실과 입원 세부 조건
- 선택 의료 항목 추가 후 결과
- 보험 설정 변경 즉시 반영
- 375px, 768px, 1280px의 가로 넘침과 focus 순서
- 콘솔 오류와 실패한 필수 요청 없음

## 제외 범위

- 계산 이력 저장과 복원
- 결과 공유·인쇄
- 의료 데이터 최신화
- 계산 공식 변경
- 비용별 SEO 페이지와 관리자 화면 변경
- 표시 버전 변경, commit, push, 배포

## 완료 기준

1. 필수 조건만으로 결과까지 도달하는 기본 경로가 동작한다.
2. 기존 고급 검색과 의료 항목 추가 기능이 유지된다.
3. 중복되거나 존재하지 않는 `결과보기` 안내가 없다.
4. 선택 요약과 초기화가 키보드·모바일에서 동작한다.
5. 기존 자동 테스트와 실제 Chrome 회귀 검증이 통과한다.
